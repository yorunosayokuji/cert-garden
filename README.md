## 元のフォルダと、この公開用の写しの違い

- 作者のローカルにある「元のアプリフォルダ」が正本です。
- このリポジトリは、そこから**専用の生成ツールで作った写し**です。手で直さず、元を直して作り直します。
- 写しには、動かすのに必要なコード・試験・設定・自作の絵だけを入れています。内部の作業メモ、参考にした他社の画像や動画、認証情報、生ログは入れていません。
- 入っているファイルの一覧（パス・大きさ・ハッシュ・ライセンス）は `PUBLISH_MANIFEST.json` にあります。ハッシュと大きさは生成時の実際のバイト列で、Gitでも改行の自動変換はしません（`.gitattributes` で `* -text`）。

## 動きの方針と、残っている過去の試作コード

キャラクターの動きは、**全身をコマごとに描いた連番画像**で作る方針です（体の分解・骨組み合成・変形は採りません）。
`mobile/` には、過去に試した合成方式の試作コードと試験（旧rig・過去の動きの比較用データ）が**記録として残っています**。これらは今のアプリが採用している動きではありません。試験を減らさないために削除していません。

## iOSの製品の入口と、公開前の検査（ローカルでできる範囲）

- **入口**: iOSでは、画面の案を `mobile/release-selection.json` の `approvedVariant`（1〜5、未選択はnull）で決めます。環境変数・URL・保存からは変えられません。未選択の署名版は「起動できません」を出して止まります。
- **比較の道具**（5案の見比べ・読込の固定・故障の差し込み・人工の待ち・「新しい動き」の見くらべ）は開発用の別の入口にあり、製品の書き出しには入りません（書き出したバイトコードの中身まで検査しています）。比較の入口は、開発ビルド（`__DEV__`）かつ比較用フラグの時だけ開き、署名版では開きません。
- **起動時**: 製品は、保存の空間が決まるまで個人のデータを描かず、箱庭の骨組みを出します（人工の待ちなし）。
- **保存**: iOSの製品は、端末の既存の保存（学習・部屋・手帳など9項目）をそのまま「ゲストの元データ」として読みます。アカウントから復元した内容は別の領域に置き、ログアウトや別アカウントのログインでは見えません。
- **EASビルド前の検査**（`mobile/package.json` の `eas-build-pre-install`）: profileが空・未知、iOS以外、署名ビルド（preview / production）で画面が未選択・bundle ID / owner / projectId / API(HTTPS) / GoogleクライアントIDが欠けている、比較用フラグや秘密らしい公開変数が混ざっている、のいずれかなら止めます。依存のinstallより前に動きます。
- **送るソースの検査**: `npm run check:eas-source`（mobile、読むだけ）。専用のGitで、コミット済み・cleanで、HEAD・index・作業ツリーのバイトが `PUBLISH_MANIFEST.json`（パス・sha256・大きさ）と一致し、リンクの逸脱や一覧に無いファイルが無いことを確認します。EAS CLIは呼びません。
- **iOS向けの書き出し**: `npm run export:ios`（製品相当・Hermes）、`npm run export:ios:compare-dev`（比較の開発ビルド相当。配布物ではありません）、`npm run export:ios:flag-release`（補助検査）。JSとassetsの書き出しの確認で、**ネイティブのコンパイル・署名・実機・TestFlightは行っていません**。
- **通信設定とFaceID**: 製品相当のビルドはHTTPSのみ（App Transport Securityを無効にしません）。開発ビルドだけ開発サーバー用の既定を残します。使っていないFaceIDの文言は出力しません。
- 未完: 画面の案の選択、Apple / EAS のアカウント、実OAuth、署名ビルド、実機での確認、App Storeの審査。

## 構成

| フォルダ | 中身 |
|---|---|
| `src/` `test/` `demo/` | 画面に依存しない学習コア（出題・復習・成長・保存）と、その試験 |
| `mobile/` | Expo + React Native のアプリ（iOS向け、Webでも確認可） |
| `server/` | Cloudflare Workers + D1 のバックエンド（ローカル検証のみ） |
| `design-assets/` | アプリが実際に読む絵と教材データだけ（全素材の置き場ではありません） |

## 技術の選定理由

| 技術 | 理由 | 限界 |
|---|---|---|
| Expo + React Native + TypeScript | 一つのコードでiOS中心に作れ、既存の学習コアを再利用できる | 実機・署名はこれから |
| 学習コア（TypeScript） | 画面と分けて、試験で壊れにくくする | 試験が通っても教材の正しさや試験範囲は保証しない |
| Cloudflare Workers + D1 | 軽量なAPIとSQL保存を一か所にまとめられる | 本番は未作成。ローカルのDBだけでは本番の合格にならない |
| jose（JWT検証） | 標準的な署名検証をサーバーで行う | 実際のGoogle/Apple接続は未実施 |
| Expo Haptics 等 | 触覚などiOSらしい反応 | 実機でしか確かめられない |

## 自分の環境で再現する

Node.js 24 以上が必要です。フォルダごとに別の `package-lock.json` があります。

```sh
# 学習コア
npm ci
npm run typecheck
npm test

# モバイル（Webの書き出しまで。ブラウザーは使いません）
cd mobile
npm ci
npm run typecheck
npm test
npm run export:web

# サーバー（ローカルの試験のみ）
cd ../server
npm ci
npm run typecheck
npm test
npm run test:preflight
```

`mobile/` の `npm run e2e` は別途ブラウザーが必要なので、CIでは動かしません。

## GitHub Actions で確かめていること

型検査・単体試験・Webの書き出しだけです（秘密情報や公開・デプロイの手順は入っていません）。
サーバーの試験はCloudflareの実行環境とローカルDBで動かすもので、本番の設定確認（未設定の項目の検査）はCIの合格条件にしていません。
CIが緑でも、**iOS署名・実機・実際のログイン・Cloudflare本番が動いた証明にはなりません**。
